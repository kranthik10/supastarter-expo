# ADR-004 — API Architecture (Hono + tRPC)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Context:** Mobile client needs a strongly typed contract (§11) but webhooks and billing callbacks are plain REST.
- **Decision:** Hono as HTTP layer, tRPC v11 for all typed procedures, with a `/api/rest/*` fallback for webhooks (Stripe, RevenueCat, health). Client uses `@trpc/client` + `httpBatchLink` + `superjson`, wrapped in TanStack Query hooks so existing `useQuery`/`useMutation` shape is preserved.
- **Alternatives:** REST-only (OpenAPI), GraphQL (codegen overhead), Expo API Routes (insufficient for auth/billing separation).
- **Consequences:** End-to-end types without codegen; REST kept only where external providers require it; procedure auth via `protectedProcedure` + `enforce(permission)`.
