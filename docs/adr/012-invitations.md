# ADR-012 — Invitations lifecycle + ownership transfer

- **Status:** Accepted — implemented in Phase 3.2
- **Date:** 2026-09-01
- **Context:** Existing `invitations` table had `token` + `expiresAt` but no lifecycle state; `organizationMembers` is the source of truth, and `owner` is a singleton per org. Phase 3 adds create/accept/revoke/expire plus ownership transfer without introducing a new role.
- **Decision:** Add `invitations.status enum(pending,accepted,revoked,expired)` + `respondedAt` + an organization index and partial unique `(organization_id,email) WHERE status='pending'`. Do not add a plaintext six-character code; the secure token is sufficient. New tokens are server-generated with 32 random bytes, stored as SHA-256 digests, and never returned in API projections; the raw token exists only in the email/deep-link transport boundary. Accept/decline hash the presented token before lookup and retain one bounded legacy lookup for pre-hardening plaintext rows, migrating them to a digest on terminal transition. Canonical tRPC procedures are server-enforced with membership/`assertCan` checks; `accept` requires an authenticated, verified email matching the invitation and consumes the token transactionally. `organizations.transferOwnership` is owner-only and atomically swaps `owner→admin` and member→`owner`.
- **Alternatives:** Custom roles (rejected — `owner/admin/member` + existing matrix suffices), separate `membership_requests` table (rejected — invite is sufficient for starter), plaintext join code (rejected — unnecessary brute-force surface), separate `declined` enum (rejected for smallest compatible delta — decline uses terminal `revoked` plus `reason=declined` and distinct audit action).
- **Consequences:** `members.update` remains owner-only; transfer is the only owner-mutation path. Every lifecycle/team transition writes `audit_logs`; token metadata is SHA-256 only. Invitation persistence is independent of email delivery and currently reports `not_configured` through a safe no-op provider. Create/redeem have an interim process-local rate limit; distributed enforcement remains required before multi-replica production deployment.
