# ADR-010 — EAS Deployment Strategy

- **Status:** Accepted
- **Date:** 2026-08-31
- **Context:** Expo apps need dev, preview, and production distribution with credentials, OTA, and store submission (§21).
- **Decision:** EAS Build + EAS Update. Three profiles in `eas.json`: `development` (dev client, internal), `preview` (internal distribution, channel `preview`), `production` (store, autoIncrement, channel `production`). OTA via `eas update` for JS-only changes. CI builds preview on `main`, production on tags.
- **Alternatives:** Bare Fastlane, manual Xcode/Gradle.
- **Consequences:** Credentials managed by EAS; dev builds required for OAuth/notifications/native modules; Expo Go stays viable only for UI iteration.
